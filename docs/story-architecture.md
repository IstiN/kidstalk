# Архитектура интерактивных историй

Цель: добавлять новые истории и сцены без изменения плеера, панели фразы и системы озвучивания. Слова, изображения, анимации и состояние сцены связаны декларативно, но реализованы независимо.

## Поток воспроизведения

```text
Манифест истории
      │
      ▼
StoryPlayer ───────────────► SpeechController
      │                         озвучивает слово
      │
      └─────────────────────► Scene.perform(action)
                                проигрывает осмысленное действие
      │
      ▼
Следующее слово начинается после завершения речи И анимации
```

Плеер не знает, что такое зайка, дождь или скамейка. Он работает только со словами, событиями и именами действий.

## Основные модули

| Модуль | Ответственность |
|---|---|
| `src/stories/bunny.js` | 15 слов и состояния истории «Зайка». |
| `src/stories/cat.js` | 12 слов и состояния авторской истории «Котик и мячик». |
| `src/stories/index.js` | Реестр доступных историй и выбор истории по ID из `?story=...`. |
| `src/app/StoryPlayer.js` | Последовательность шагов, синхронизация речи и анимации, отмена запуска, события для UI. |
| `src/scenes/index.js` | Ленивый `import()` нужной сцены по `story.scene`; код других миров не загружается. |
| `src/scenes/bunny/BunnyScene.js` | Парк, зайка, скамейка, хозяйка, туча и дождь. |
| `src/scenes/cat/CatScene.js` | Комната, котик, мама, мячик, стул и окно. |
| `src/scenes/core/TweenManager.js` | Отменяемые переходы и ожидания. Отдельно от постоянной анимации дождя и дыхания. |
| `src/symbols/renderSymbol.js` | Адаптер изображений: ARASAAC или локальный SVG. |
| `src/speech.js` | Системный голос выбранного языка (`utterance.voice` не задан), скорость, mute и Web Speech API. |
| `src/i18n.js` | Русский, английский и беларуский UI; переводы манифестов по стабильным ID без изменения действий и символов. |
| `src/main.js` | Маршрут: `/` → каталог, `?story=id` → история, `?story=id&print=1` → печатная книжка. Все страницы загружаются лениво. |
| `src/catalog.js` | Landing-каталог; создаёт карточки по реестру и не загружает Three.js. |
| `src/storyPage.js` | Карточки, панель фразы, кнопки и отображение событий плеера. Не содержит сценарной логики актёров. |
| `src/printPage.js` | Статическая A4-книжка: обложка, страницы строк, локализованные слова и пиктограммы; Three.js не загружается. |

`src/story.js` и `src/scene.js` оставлены только как backward-compatible entry points; новая логика находится в `stories/` и `scenes/`.

## Манифест слова

```js
{
  id: 'slezt',
  word: 'слезть',
  action: 'attemptDown',
  minDuration: 2100,
  caption: 'Зайка наклоняется вперёд и осторожно тянет лапку вниз.',
  symbol: {
    set: 'arasaac',
    id: 8035,
    sourceWord: 'спускаться',
  },
  pauseAfter: 180,
}
```

- `id` — стабильный идентификатор внутри истории;
- `word` — текст и произносимая форма;
- `action` — семантическое действие, реализованное сценой;
- `minDuration` — минимальная длительность шага без звука;
- `caption` — объяснение действия ребёнку и взрослому;
- `symbol` — независимый источник изображения;
- `pauseAfter` — пауза перед следующим словом.

Русская подпись не обязана совпадать с исходным названием пиктограммы. Например, символ «спускаться» может подписываться «слезть» в соответствии со стихотворением.

## Локализация

`src/i18n.js` накладывает переводы на копию базового русского манифеста. Стабильные `story.id`, `line.id` и `word.id` являются ключами локализации; `action`, `symbol`, `minDuration`, `initialState` и `elements` остаются общими для всех языков. Поэтому перевод не требует отдельной сцены и не меняет сценарий анимации.

В режиме **«Авто»** язык определяется из `navigator.languages` / `navigator.language`; при переходах `lang` не добавляется в URL и не блокирует автодетект. Ручной выбор записывается в `?lang=ru|en|be` и `localStorage`. Повторный выбор **«Авто»** очищает оба явных параметра. Ссылки между каталогом, историей и печатью сохраняют выбранный режим. `SpeechController` получает соответствующую локаль (`ru-RU`, `en-US`, `be-BY`), но не назначает конкретный `utterance.voice`: рабочий голос выбирает операционная система.

При добавлении истории переводятся метаданные, `initialCaption`, `finalCaption`, каждый `word`, каждый `caption` и `extraWords`. Если перевод ещё не добавлен, используется русское значение как безопасный fallback.

## Печатная книжка

`?story=<id>&print=1&lang=<language>` создаёт обложку и одну альбомную A4-страницу на каждую строку. Слева печатаются слова, символы и пояснения, справа — общая SVG-сцена строки. Параметр `coloring=1` и кнопка **«Раскраска»** убирают цветную заливку и преобразуют растровые пиктограммы в контуры. Кнопка печати дожидается готовности изображений и вызывает `window.print()`; CSS `@page` задаёт `A4 landscape`. Печатная обложка сохраняет атрибуцию ARASAAC.

## Общие иллюстрации и превью

`src/printScenes.js` является общим источником векторных сцен для печати и превью. `npm run previews` читает реестр историй и создаёт `public/previews/<id>.svg`; `npm run build` запускает генератор автоматически. Поэтому превью не зависят от разрешения экрана и не дублируют исходный код рисунков.

В манифесте можно выбрать `previewScene` и `previewLine`, если обложка должна показывать другой мир или строку. Вместо генерируемого SVG разрешён внешний HTTPS-URL в `preview` — например, для открытого лицензионного набора изображений. Такие файлы генератор пропускает; лицензия и атрибуция остаются обязательными.

## Компактная горизонтальная раскладка

Для landscape viewport шириной от 600px и высотой до 600px `story-shell` включает отдельную рабочую раскладку: компактные переключатель историй и фраза сверху, карточки слева, сцена справа. Дополнительный режим до 360px высоты уменьшает только вторичные отступы и сохраняет подписи карточек. Вспомогательные intro, steps и footer скрываются; интерактивные элементы остаются доступны без прокрутки страницы. Вертикальная раскладка не изменяется.

## Точки расширения для обучающих режимов

- Новая история подключается через реестр `src/stories/index.js`, а новый мир — через lazy loader `src/scenes/index.js`.
- Стабильные `story.id`, `line.id`, `word.id` позволяют добавлять переводы, прогресс, подбор заданий и статистику без изменения текста сцен.
- `StoryPlayer` выдаёт события начала/завершения слова и последовательности. Режимы «повтори», «найди слово», «собери фразу» и проверку произношения следует подключать отдельными контроллерами к этим событиям, не встраивая обучающую логику в Three.js-сцену.
- `symbol` не связан с анимацией: источник изображения можно заменить или расширить через `renderSymbol`, сохранив сценарий слова.
- Общие SVG-иллюстрации выбираются по `story.scene`; новая история может переиспользовать существующий мир, арт, действия и слова.

## Контракт сцены

Каждая сцена возвращает небольшой общий интерфейс:

```js
{
  perform(action, context), // Promise<boolean>: осмысленное действие
  cancel(),                 // отменить переходы, оставив постоянный рендер
  reset(initialState),      // установить начальную контрольную точку
  setRain(enabled),         // пример scene-specific публичной команды
  destroy(),                // освободить renderer, geometry, materials, observers
}
```

`perform` не должен самостоятельно озвучивать слово или менять панель фразы. Сцена отвечает только за визуальное действие. Команды вроде `setRain` нужны только тем мирам, где соответствующий контрол показан в UI.

### Интерактивные предметы

Сцена принимает `onElementClick(elementId)`. Raycast определяет предмет, а манифест связывает его со словом:

```js
elements: {
  bunny: 'zayka',
  bench: 'skameyki',
  cloud: 'tucha',
},
extraWords: [
  { id: 'tucha', word: 'туча', action: 'focusCloud', minDuration: 1300 },
],
```

- Обычные `elements` могут ссылаться на карточку истории.
- `extraWords` добавляет слова для объектов, которых нет в тексте: «туча», «окно». Они озвучиваются, но не попадают в полный сценарий.
- Нажатие на предмет не добавляет слово в «Мою фразу» автоматически; фразу ребёнок собирает карточками.
- Для тонких/составных моделей разрешены прозрачные hit area. Они не меняют картинку, но увеличивают сенсорную цель.
- Стрелки на сфокусированном canvas перебирают предметы, Enter повторяет текущий.

### Два типа движения

1. **Семантические переходы** — уход хозяйки, наклон, вытянутая лапка, капля от ушей до швов. Они выполняются через `TweenManager`, возвращают Promise и отменяются.
2. **Постоянное движение** — дождь, дыхание, лёгкое покачивание облаков. Оно обновляется в render loop и не блокирует слова.

Не смешивать эти типы: иначе слова снова начнут запускать короткие, независимые друг от друга эффекты.

## Тайминг

Для каждого слова плеер ждет обе задачи:

```js
await Promise.all([
  speech.speak(word.word),
  scene.perform(word.action),
]);
```

Поэтому короткое произношение «бросила» не обрезает медленный уход хозяйки. В mute-режиме речь заменяется ожиданием `minDuration`, но анимация всё равно выполняется.

`prefers-reduced-motion` сокращает переходы через `TweenManager` и отключает непрерывные лишние движения. Смена поз и смысловые состояния сохраняются.

## Отмена

У `StoryPlayer` есть монотонный `runId`. Новое нажатие:

1. увеличивает `runId`;
2. отменяет текущую речь;
3. вызывает `scene.cancel()`;
4. делает устаревшим результат предыдущего асинхронного сценария.

`TweenManager.cancel()` завершает активные переходы с результатом `false`. После каждого `await` действие проверяет результат и не запускает следующий фрагмент поверх нового.

## Контрольные точки строк

Строка может проигрываться отдельно. Поэтому она объявляет состояние мира до своего первого слова:

```js
{
  id: 'line-3',
  initialState: { owner: 'away', rain: true, wet: 0.12 },
  words: [/* со скамейки… */],
}
```

Для «Зайки»:

- первая строка: хозяйка рядом, сухо;
- вторая: хозяйка уже ушла, дождь ещё не начался;
- третья: хозяйки нет, дождь уже идёт;
- четвёртая: дождь идёт, зайка уже частично влажный.

Это устраняет внезапное появление/исчезновение актёров при запуске строки вне полной истории. Новый набор состояний должен интерпретироваться конкретной сценой, а не `StoryPlayer`.

## События плеера для UI

- `stop`;
- `sequenceStart`;
- `wordStart`;
- `wordEnd`;
- `sequenceEnd`;
- `phraseStart`;
- `phraseEnd`.

`storyPage.js` использует их для подсветки карточек, кнопок остановки, подписей и live region. Сцена не изменяет DOM карточек напрямую.

## Как добавить новую историю

1. Создать `src/stories/<story-id>.js` с метаданными, строками и `initialState`.
2. Подобрать символы и сохранить лицензионные метаданные. Исследование: `docs/aac-symbols.md`.
3. Если история происходит в существующем мире, переиспользовать его `action` или добавить новые семантические методы сцены.
4. Для нового мира создать `src/scenes/<scene-id>/`, реализовать контракт сцены и зарегистрировать lazy loader в `src/scenes/index.js`.
5. Добавить историю с `emoji`, `subtitle`, `shortDescription`, `tags` и `preview` в `src/stories/index.js`. Для общей SVG-сцены указать `/previews/<story-id>.svg` и запустить `npm run previews`; для открытого внешнего изображения — HTTPS-URL и его лицензию.
6. Landing и переключатель историй создаются автоматически по реестру. Новая история открывается по `?story=<story-id>` с полной загрузкой страницы, поэтому ресурсы предыдущей сцены освобождаются браузером. Корень `/` остаётся лёгким каталогом без WebGL.
7. Добавить `elements` для нажимаемых объектов и `extraWords`, если объект не назван в тексте.
8. Проверить полную историю, каждую строку отдельно, клики по объектам, mute, отмену на каждом действии и мобильный viewport.

## Правила хорошей сцены для AAC

- Одно слово — одно явное изменение позы, места или состояния.
- Не полагаться только на текст: действие должно быть видно без чтения.
- Не начинать погоду и другие события заранее, если у них есть отдельное слово.
- Не телепортировать персонажа без потребности; показывать начало, направление и завершение движения.
- Давать достаточно времени: следующее слово не должно обрезать действие.
- Для предлогов показывать отношение объектов: «под» — туча сверху, «до» — путь капли.
- Для «не смог» сначала показать попытку, затем отказ/возврат, а не только грустное лицо.
- Любое слово можно повторить отдельно; повтор не должен оставлять конкурирующие анимации.
